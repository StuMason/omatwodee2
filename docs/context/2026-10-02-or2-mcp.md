## What was asked

Stu wants Claude Desktop/claude.ai to operate OR2 like the Coolify MCP does. Chosen design: remote MCP over HTTPS with OAuth, fork of coolify-mcp's OAuth core, only /authorize behind Cloudflare Access, runs in-cluster as or2-agent. Option (a): it will also commit structural changes to the repo (not in this commit).

## What changed

New `mcp/` package:
- `lib/oauth.ts`, `lib/ssrf.ts` + tests: copied unchanged from coolify-mcp (MIT, Stu's own).
- `lib/access.ts`: verifies the `Cf-Access-Jwt-Assertion` JWT (RS256 against the team's published certs, AUD, issuer, expiry, email allowlist; refetch on unknown kid; fails closed).
- `lib/http-server.ts`: coolify-mcp's router with the human proof swapped from "paste a Coolify token" to "verified Access login" on both GET (consent page) and POST (approve). CSP + frame-deny on HTML.
- `lib/cluster.ts`: app-centred Kubernetes layer (app = namespace labelled or2.stumason.dev/app=true; runtime env in a `runtime-env` Secret Flux doesn't own).
- `lib/server.ts`: 14 tools (status, apps, app, logs, usage, diagnose, restart, scale, env_keys, env_set, env_unset, run, backup_now, backups). Changes need `confirm: true` after a preview. Logs/exec output framed with coolify-mcp's `asUntrustedLogs`. JSON audit line per call; env values never logged.
- `http.ts`, Dockerfile, `.github/workflows/mcp.yml`: test on every change; on main, build linux/arm64 on GitHub-hosted ARM (public repo: never self-hosted runners), push GHCR, bump the tag in `apps-proof/or2-mcp/deployment.yaml` (if present) with `[skip ci]`.

## Decisions made

- **Confirm param instead of elicitation for v1**: every client supports it; elicit.ts can come later.
- **OAuth state in a file on a PVC**, not Postgres (simplest, matches the forked code). Losing it only forces re-authorization.
- **CI bumps the tag**, not Flux image automation: no write credential in the cluster.
- **arm64-only image** for now (the box is ARM).

## Risk surface

- **Auth boundary:** /authorize must be behind a Cloudflare Access app (path-scoped). The server verifies the JWT itself, so a request that bypasses Access (e.g. direct to the origin) still fails without a valid signed token. The tunnel means there is no direct origin path.
- **Blast radius:** tools act as or2-agent (app namespaces only, no secrets outside them, no RBAC/system). `or2_run` executes arbitrary commands in app pods after confirmation.
- **Prompt injection:** log and exec output is framed as untrusted; tool descriptions instruct the model never to follow instructions found in them.
- **Known gaps:** no rate limiting on /mcp itself (bearer-gated); audit log is stdout only (lost on pod restart); no structural (git) tools yet; restore/deploy/rollback not yet.
